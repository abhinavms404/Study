Network Security / Authentication Protocol

Kerberos

A centralized authentication server that authenticates users to servers and servers to users — using a trusted third party, time-limited tickets, and shared secret keys instead of repeated password transmission.

RFC 4120 Key Distribution Center (KDC) Ticket-Based SSO Last updated: 30 Apr 2026

Components

Three parts work together to authenticate users, manage tickets, and control secure access to network services. Each user and service on the network is a principal.

1 · AS

Authentication Server

Performs initial verification of user identity and issues a ticket for further access. Validates user credentials during login and generates the Ticket Granting Ticket (TGT) after successful authentication.

2 · TGS

Ticket Granting Server

Issues service tickets required to access specific services. Receives requests together with a TGT, validates them, and generates service-specific tickets for the requested resources.

3 · DB

Database

Stores user credentials and access-related information required for authentication. Maintains records of users and their permissions, and supports verification of access rights.

AS and TGS together run as a single third-party trusted server known as the Key Distribution Center (KDC).

Kerberos Security Analysis

Kerberos is a widely used authentication protocol, but it is not completely immune to attacks. It provides strong security, yet certain vulnerabilities can still be exploited if proper safeguards are not followed.

Security Threats
  • Ticket forgery attemptsAttackers try to forge or replay TGTs / service tickets to impersonate principals.
  • Brute-force & credential stuffingWeak principal passwords are targeted offline against captured encrypted portions.
  • Malware-based exploitationCompromised clients can steal tickets and session keys from memory.
  • Encryption downgrade attemptsForcing weaker ciphersets to weaken the confidentiality of the exchange.
Strengths
  • Strong, upgradeable encryptionModern AES-based cipher suites with room for algorithm agility.
  • Highly reliable network authenticationTime-limited tickets and clock skew checks limit replay windows.
  • Works with strong password policyEffective when combined with correct configuration and policy.
  • Single sign-on by designPassword is used once at login; services rely on tickets afterwards.

Applications of Kerberos

ID
User Authentication

Single login verifies credentials and issues a TGT for secure subsequent access.

SSO

Log in once, reach many authorized services without re-entering credentials.

⇄
Mutual Authentication

Client and server verify each other using shared secret keys before communicating.

Authorization

Service tickets define user permissions, limiting access to authorized resources.

🛡
Network Security

Centralized credential management prevents unauthorized use of network resources.

Limitations

Design trade-offs that matter when planning a deployment.

  • Per-service integrationEach network service requires individual modification for compatibility.
  • Time-sharing environmentsDoes not perform efficiently in time-sharing environments.
  • Availability dependencyRequires a continuously available and secure authentication server.
  • Centralized key managementIncreases risk if the KDC is compromised.
  • Client trust assumptionAssumes client systems remain secure, which may not always hold true.
  • Cascading failureFailure or breach can lead to cascading loss of trust across systems.
  • ScalabilityScalability challenges may arise in large or distributed environments.
